## 0. 一句话概括手工流程

> 从工作区取材（简历 + 图片 + 视频 + PSD/AEP）→ 规整成 `assets/` → 生成单文件 `index.html`
> → 指定视觉风格 → 设计评审打分 → 按评审重写 → 加动效 → **截图自检** → 查敏感信息 → 发布。

其中**「设计评审打分」和「截图自检」是最有价值的两步**，也是手工做时最耗时、最容易漏的，正好最适合程序接管。

## 1. 九个阶段（手工实录 → 程序步骤）

| # | 阶段 | 手工怎么做的 | 程序能否自动 | 归属模块 |
| --- | --- | --- | --- | --- |
| 0 | 初始化 | 建 `rule.md`（规则）+ `log.md`（进度日志），每阶段更新 | ✅ 纯代码 | `lib/generate.js` |
| 1 | 取材 | 在工作区搜简历 docx / 图片 / 视频 / PSD / AEP，读文本 + 看图判断用途 | 部分（需多模态 LLM） | `lib/assets.js` + LLM |

| 3 | 生成骨架 | 单文件 `index.html`，内嵌 CSS+JS，纯静态，双击可开；先结构→再样式→再交互 | ✅ LLM | `lib/generate.js` |
| 4 | 风格定向 | 给一个风格库（如韦斯·安德森 6 部片），让模型**选一部并说明理由**，产出色板 | ✅ LLM | `lib/generate.js` |
| 5 | **设计评审** | 6 维度打分 + 逐项失分原因 → **按评审结论重写** | ✅ LLM | `lib/review.js` |
| 6 | 加动效 | 10 项候选菜单，按气质选配（Level 1/2/3），尊重 `prefers-reduced-motion` | ✅ LLM | `lib/generate.js` |
| 7 | **截图自检** | 生成桌面+移动端截图，查 JS 错误 / 资源错误 / 横向溢出 / 文字重叠 | ✅ **Electron 直接能做** | `lib/selfcheck.js` |
| 8 | 敏感信息 | 手工扫一遍并列表格 | ✅ 已有 21 条规则 | `lib/scanner.js` |
| 9 | 发布 | git push + Pages | ✅ 已有 | `lib/deploy.js` |

**结论**：阶段 2、7、8、9 可以纯代码完成（不需要 LLM）；阶段 1、3、4、5、6 需要 LLM。所以**即使没有 API key，也能先做完一半**。

## 2. 从对话里抠出来的硬约束（这些是踩过的坑，直接写进代码）

这七条是手工做的时候**真出过问题**才发现的知识，价值最高：

| # | 约束 | 出处（手工时的真实经历） |
| --- | --- | --- |
| C1 | **素材文件名必须是 ASCII / 拼音**，不能有空格和特殊字符 | 原话："用拼音命名，避免空格和特殊字符" |
| C2 | **视频必须是 H.264**，HEVC 浏览器播不了，要转码 | 两个原片 HEVC → 转 H.264（168MB→75MB） |
| C3 | **PSD / AEP 不能直接展示**，要导出预览图 | 179MB PSD → 导出预览图入站；AEP 只在技能标签佐证 |
| C4 | **视频要抽首帧做封面**，否则黑屏/裂图 | 0.8s 处是黑帧，需重抽 |
| C5 | **图片路径必须写死静态 `src`**，不能靠 JS 注入 | 原话："改为静态 src（避免发布裂图）" |
| C6 | **动效元素初始 `opacity:0` 是截图盲区**，要用"动效已完成"临时副本验证 | `shot.py` 只强制 `.reveal` 容器，stagger 子元素截不到 |
| C7 | **文字重叠检测会误报**（同一行相邻加粗/数字片段），必须配截图人工确认 | 多次"5 处告警全部为检测误报" |
| C8 | **每阶段备份** `_backup/index-vN.html`，可随时回滚 | 每版都备份 |
| C9 | 单文件交付时**必须连 `assets/` 一起发**，否则裂图 | 每次都提醒"转发需连目录一起发" |

> 这九条正是「产品化」的意义：把隐性经验变成确定性检查项。

## 3. 设计评审的评分维度（可直接当 rubric 用）

手工时用的是 huashu-design 的 5 维度框架，实际输出是 6 项：

| 维度 | 手工时的实例评分 | 判什么 |
| --- | --- | --- |
| 概念 | 8.5 | 母题是否与身份强绑定、可不可替换 |
| 哲学一致性 | 7.5 | 是否所有细节都服从同一套视觉语言 |
| 视觉层级 | 7 | 对比是否够（如类别 12px 与标题对比 <2.5 倍就是不够） |
| 细节执行 | 6.5 | 间距是否走网格（8pt）、小字号是否可见、装饰是否散 |
| 功能性 | 7 | 有没有冗余内容、入口是否过多 |
| 创新性 | 8 | 有没有 AI 惯性装饰（菱形、红章这种套路） |

**关键机制**：评审不是写报告就完事，而是**按失分项直接重写**。例如"圆形头像偏现代 → 改方形报纸肖像"、"间距未成网格 → 统一 8pt"。程序要照抄这个闭环：**评审产出具体改动清单 → 带着清单重写**。

## 4. 动效菜单（Level 1「优雅档」实测选配）

手工给的 10 项候选，实测选了 7 项：

| 选项 | 实现 | 是否选 |
| --- | --- | --- |
| ① 静态 | — | ✗（与"加动效"矛盾） |
| ② 3D 装饰小元素 | 印刷浮雕 + 微缩浮动 | ✓ |
| ③ 双层 cursor | — | ✗（现代 UI 语言与复古纸质冲突） |
| ④ stagger 错位 | 组内延迟 80ms 逐张浮现 | ✓ |
| ⑤ letter-spacing 收束 | 标题字距从宽收窄 | ✓ |
| ⑥ odometer 滚动 | 数字滚动计数（easeOutCubic） | ✓ |
| ⑦ 背景色过渡 | 章节进入时纸色过渡（翻页感） | ✓ |
| ⑧ 抬起 + 投影 | hover 上浮 + 硬投影 | ✓ |
| ⑨ 信封 SVG 手写 | 笔画描边动画 | ✓ |
| ⑩ 朴素 | — | ✗ |

**铁律**：全部纯原生 CSS/JS，零库；全部尊重 `prefers-reduced-motion`。

## 5. 截图自检 —— 本项目最大的技术红利

手工时这一步依赖 huashu-design 的 `shot.py` + playwright。

**但本项目是 Electron 应用，Electron 本身就是 Chromium**：

| 手工用什么 | 我们能用什么（零依赖） |
| --- | --- |
| playwright 启动浏览器 | `new BrowserWindow({ show:false })` |
| `page.screenshot()` | `webContents.capturePage()` |
| 监听 console 错误 | `webContents.on('console-message')` |
| 检测资源加载失败 | `webContents.session.webRequest.onErrorOccurred` |
| 检测横向溢出 | `executeJavaScript('document.documentElement.scrollWidth > clientWidth')` |
| 检测文字重叠 | `executeJavaScript` 遍历元素 `getBoundingClientRect()` 求交 |

**这意味着截图自检可以零依赖实现，完全符合项目的「零运行时依赖」约定** —— 而且比 playwright 方案更轻、更快、不用下载 300MB 浏览器。

已知误报（C6/C7）要在实现里显式处理：
- 检测重叠时**跳过初始 `opacity:0` 的动效元素**，或先注入"动效已完成"的 class 再测
- 同一行相邻行内元素（`<b>`、`<span>`）的重叠判为**警告而非失败**，并在报告里附截图路径要求人工确认

## 6. 程序化后的流水线（与现有链路衔接）

```
①  需求 / 素材            ← 新增：lib/assets.js 取材与规整（纯代码）
        ↓
②  生成（LLM）            ← 新增：lib/generate.js（结构→分块→组装）
        ↓
③  设计评审（LLM）        ← 新增：lib/review.js（打分 → 改动清单 → 重写）
        ↓
④  截图自检               ← 新增：lib/selfcheck.js（Electron，纯代码）
        ↓
⑤  扫描归纳敏感信息       ← 已有：lib/scanner.js
        ↓
⑥  逐项选择打码/删除      ← 已有：GUI
        ↓
⑦  生成上线目录 + 自检    ← 已有：lib/redactor.js
        ↓
⑧  预览 → 上线 → 线上复核 ← 已有：lib/preview.js + lib/deploy.js
```

**衔接关键**：②③ 的产物必须是**标准的 `index.html` + `assets/` 目录结构**，这样 ⑤ 扫出来的"文件:行:列"才准确，⑦ 的 `lib/html.js` 状态机才能安全改写。

## 7. 无 API key 时怎么办

- `lib/llm.js` 内置 **`mock` 适配器**：返回确定性的、结构完整的示例页面（含若干种可被脱敏规则命中的合成 PII）。
- 因此 **②③④ 的全部**（生成 → 评审 → 自检 → 脱敏 → 上线）**在没有 key 的情况下也能完整跑通**，可当演示与评测基线。
- 有 key 时只需配置 provider，业务代码零改动。
