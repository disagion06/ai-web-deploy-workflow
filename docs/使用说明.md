# 使用说明 · 设计稿上线助手

> 写给**完全不懂命令行**的人。照着点，就能把电脑里的网页设计稿变成一个可以发给别人的网址。
>
> 全程你只需要做两件事：**勾选要隐藏哪些信息**，以及**登录自己的 GitHub 账号**。其余命令全部由程序执行。

---

## 一、开始之前：装一个 Node.js

程序运行需要一个叫 **Node.js** 的基础环境。

1. 打开 <https://nodejs.org>，下载 **LTS 版本**（左边那个绿色按钮）。
2. 双击安装，**保持默认选项一路「下一步」**（不要取消任何勾选）。
3. 装完**重启电脑**（或者至少关掉所有已打开的黑窗口）。

> **只有 Node.js 需要你自己装。**
> **Git** 会在后台用系统自带的 winget 自动安装；**GitHub CLI** 会自动下载官方压缩包解压到程序自己的工作目录（**不会弹管理员权限窗口**）；图片打码用的小插件也会自动安装——万一装不上，程序会自动改用「同尺寸占位图」方案，不会卡住你。

还需要：一个 **GitHub 账号**（免费注册 <https://github.com/signup>）、能访问 github.com 的网络、以及一个里面最好有 `index.html` 的设计稿文件夹。

**怎么打开程序**（任选一种，推荐前两种）：

1. **已经拿到安装包 `设计稿上线助手-安装包-x.x.x.exe`** → 双击它，一路「下一步」：

   | 安装向导里的页面 | 你要做什么 |
   | --- | --- |
   | 选择安装模式 | 默认「仅为当前用户安装」（不需要管理员密码）；想让这台电脑所有用户都能用，选「为所有用户安装」，会弹一次 UAC 授权 |
   | 选择安装位置 | 想换目录就点「浏览」，不换直接下一步 |
   | **安装选项** | 这里有一个默认**已勾选**的 **「创建桌面快捷方式（推荐）」**。想要桌面图标就别动它；不想要（只想放开始菜单）就把勾去掉 |
   | 正在安装 | 等进度条走完，最后可以勾「运行 设计稿上线助手」直接打开 |

   卸载：Windows「设置 → 应用 → 已安装的应用」里找到「设计稿上线助手」卸载，桌面快捷方式会被一起清理。

2. **拿到的是便携版 `设计稿上线助手-便携版-x.x.x.exe`** → 直接双击即用，不写注册表、不需要安装（但它不会给你建桌面快捷方式，可以自己右键 →「发送到」→「桌面快捷方式」）。

3. **拿到的是源码文件夹** → 双击文件夹里的 **`启动.bat`**（首次会自动装运行依赖，约 1~3 分钟，黑窗口滚字属正常）；或者在文件夹里 `Shift` + 右键 →「在此处打开 PowerShell 窗口」，依次执行 `npm install` 与 `npm start`。

> 💡 如果 `npm install` 卡在下载 Electron 运行库（国内网络常见），先执行 `set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 再重新 `npm install`。装完后安装脚本会打印一行自检结果，告诉你运行库是否就绪。
> 💡 双击任何脚本若出现"黑窗口一闪就关"，请双击同目录的 **`诊断.bat`**，它会生成一份 `诊断报告.txt`（含环境与启动日志），发给开发者即可定位。

**打开后你会看到**：顶部五步进度条（1 导入设计稿 / 2 敏感信息 / 3 生成目录 / 4 上线 Pages / 5 完成）；右上角显示当前站点名；左侧是当前步骤内容；右侧「环境与插件」面板显示 Node、Git、GitHub CLI、登录状态、打码插件、网络是否就绪——**这里不用你操作**，缺什么它自己装，好了还显示红的就点面板右上角「重新检测」。底部是提示文字 +「上一步 / 下一步」。菜单栏默认隐藏，按一下 `Alt` 键才出现。

## 二、第一步：开始（生成网页 或 导入设计稿）

这一步顶部有两个标签页，**你手上有设计稿就选「已有设计稿」，没有就让 AI 生成**。

### 2.1「AI 生成网页」——没有设计稿也能做

| 你会操作 | 意思 |
| --- | --- |
| 大输入框 | 用一句话说清**用途 + 内容 + 风格**。写得越具体，结果越接近你想要 |
| 灰色小标签 | 三个现成例子，点一下直接填进输入框，可以再改 |
| 视觉风格 | 简洁现代 / 报纸印刷 / 粉彩对称 / 深色科技，四选一 |
| 动效 | 「优雅档」会加淡入、数字滚动等少量动效，并且自动尊重系统的「减少动态效果」设置；不想要就选「不要动效」 |
| 模型 | 默认是「本地模拟（无需 key）」，能用假数据把整个流程走通；要真内容需选带 key 的模型（见下） |
| 素材目录（可选） | 有照片、视频、简历就选上，程序会把它们规整好后放进 `assets/` |
| 设计评审 | 勾上会多跑几次模型，按六个维度打分并列出该改的地方 |

**点「开始生成网页」**，进度条会依次显示：规整素材 → 规划结构 → 分块生成 → 组装。
完成后卡片上会出现「**继续：扫描敏感信息**」按钮，点它就直接进入第二步。

> ⚠️ **重要**：AI 生成的页面里很可能带着你给它的真实手机号、邮箱、照片拍摄地点。
> 所以生成之后**一定要走第二步**逐项处理，不要直接上线。

> 想用真模型：到 platform.deepseek.com 注册并创建 API key，然后在启动程序前设置环境变量
> `DEEPSEEK_API_KEY`；模型下拉框里就会出现可用的 DeepSeek。选「本地模拟」时内容是占位示例，**不适合真发布**。

### 2.2「已有设计稿」——导入做好的文件夹

**你会看到**：一个大的虚线框「**把设计稿文件夹拖到这里**」，下面两个按钮。

| 按钮 | 意思 |
| --- | --- |
| 选择文件夹 | 一次性选中整个站点目录（推荐，图片样式才能一起上线） |
| 选择 index.html | 只选网页入口文件，程序自动取它所在目录 |
| 「正在扫描敏感信息…」 | 程序正在统计文件、检查照片的拍摄信息、找手机号/邮箱/身份证等。大站点要十几秒，**别关窗口** |

**你该点**：把整个设计稿文件夹**拖进虚线框**，或者点「选择文件夹」选中它，点「就用这个文件夹」。也可以点「选择 index.html」直接选入口文件。

**扫描完成后你会看到**一张「站点概览」卡片：

- **入口文件**（例如 `index.html`；若显示「未找到」会有一条黄色提示）、**文件总数**、**总体积**、**图片数量**；
- 「**最大的 5 个文件**」表格（带占比条）；
- 可能出现的提示框：「这些文件超过 50MB，GitHub 上传会变慢甚至被拒」（记住它们，第 3 步可以勾选不上传）、「没有找到 index.html 入口」、「扫描提示」（例如「除入口外还有 3 个 HTML 文件，它们同样会被公开访问」）；
- 底部「共 N 项需要确认」+ 蓝色按钮「**开始逐项确认 →**」。

**没有 index.html 怎么办？**

- 入口文件叫别的名字（如 `main.html`）→ **改名成 `index.html`** 最省事；不改也能上线，只是访问链接要带上文件名。
- 入口藏在子目录里（如 `作品集/dist/index.html`）→ 直接把那个**子目录**拖进来。
- 目录里有**多个**含 `index.html` 的子文件夹 → 程序不会替你猜，会报错并列出候选，请直接选中其中一个。

看完点右下角「**下一步**」。

## 三、第二步：逐项选择隐藏方式

这是最需要你动脑的一步，也是程序的核心价值。

**你会看到**（从上到下）：

1. **一排数字统计**：共 N 项 / 高危 / 中危 / 将打码 / 将删除 / 将隐藏整块 / 仍保留（随你的选择实时变化）。
2. **筛选标签**：「全部」「联系方式」「身份信息」「账号凭据」「位置信息」「教育职业」「图片」，各带条数。
3. **四个批量按钮**：「全部打码 / 全部删除 / 全部隐藏整块 / 全部保留」——**只作用于当前筛选出来的条目**。
4. **条目列表**，分「文本类敏感信息」和「图片」两节：

   **文本条目（例：一条邮箱）**

   ```
   [demo@example.com] → de***@example.com   [邮箱地址] [联系方式] [中危]
   公开邮箱会被爬虫抓取用于垃圾邮件；求职场景可保留。  出现 3 次  index.html
   查看命中位置（3）                          ← 点开看每一处在哪
   ── 右侧：[ 打码 | 删除 | 隐藏整块 | 保留 ]   ← 四选一，点一下即生效
   ```

   - `→ de***@example.com` 是**打码后真正会变成的样子**，不是示意图。
   - 「查看命中位置（3）」展开后逐条给出 `index.html:476:30`、位置种类（文本/属性/注释/原始文本）、所在标签与属性（如 `<a> @href`），以及一段代码，**命中的词用 `⟪ ⟫` 圈出来**。

   **图片条目（例：一张工作照）**

   ```
   [缩略图] assets/portrait-demo.png [人像照片] [含拍摄地点(GPS)] [含 EXIF 元数据]
            1920 × 2880   2.4 MB   默认建议：打码
            ⚠ 照片含拍摄地点坐标（24.88, 102.83）
            设备 Apple · iPhone 13 · 软件 17.4 · 拍摄 2024:03:11 15:22:08
   ── 右侧：[ 模糊打码 | 删除 | 保留 ]        ← 三选一（没有「隐藏整块」）
   ```

5. **最下面「自定义关键词」卡片**：输入框 +「添加」。适合补上程序猜不到的内容（真实姓名、宿舍楼号）。命中的条目会**置顶**并标「自定义命中」；真正打码发生在第 3 步生成时，命中内容一律打码。**注意：加关键词不会让列表新增条目**，该逐条看的还是要看。

**你该点**：一条条看，逐条点右侧按钮。拿不准就先不动——程序已为每条算好「默认建议」，不动就是采用建议值。实在懒得看，点「全部打码」也能得到安全的结果（代价是页面出现一堆星号）。

做完点「**下一步**」。若提示「请先导入设计稿」，说明上一步没完成。

## 四、第三步：勾选大文件并生成

**你会看到两张卡片。**

**卡片一：大文件清单**——没有超过 50MB 的文件时只写一句「没有超过 50MB 的大文件，无需处理」；有则是一张表格：`排除`（勾选框）/ `文件` / `体积` / `处理`。表格上方写着「勾选 = 该文件『不上传』……默认全部勾选框为空，即全部上传」。

**卡片二：生成选项**

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| ☑ 清除照片里的 EXIF 与拍摄位置 | **已勾选** | 推荐保持。手机照片常带 GPS 坐标、设备型号、拍摄时间 |
| ☐ 在页面底部加一行「已脱敏」提示 | 不勾选 | 勾了会在网站最下方加一行灰色小字「本页面已做个人信息脱敏处理 · 由「设计稿上线助手」生成」 |
| 站点标题（可选） | 留空 | 填了就替换网页标签页上的标题 |
| 「生成上线目录」按钮 | — | 开始脱敏并输出 |
| 「打开工作区目录」按钮 | — | 在资源管理器里打开输出位置 |

**你该点**：① 给不想上传的文件打勾；② 保持 EXIF 清除勾选；③ 点「**生成上线目录**」。

**生成完成后你会看到**「生成结果」卡片：文件数 / 体积 / 整块隐藏处数；「已处理：」列表；「**仍将公开：**」列表（**这一节很重要**，凡你选「保留」的内容都在这里）；「已排除的文件」；以及一条绿色「**没有残留的敏感信息**」或黄色「**仍有 N 项敏感信息被保留**，这些内容将原样公开在网上」。旁边还有「打开目录」「打开脱敏报告」。

接着是「**本地预览**」卡片：点「**本地预览**」→ 程序起一个本地服务器并**自动用浏览器打开**，界面上出现 `http://127.0.0.1:xxxxx/` 链接和「停止预览」按钮。请**把整页翻一遍**：照片糊了吗、该没的信息没了吗、排版塌了吗。

> 如果出现黄色提示「仍有 N 项敏感信息被保留」，请点「上一步」把它们改成打码/删除/隐藏整块，再重新生成一次。

确认无误后点「**下一步**」。

## 五、第四步：登录并上线

### 卡片一：GitHub 账号

**没登录时**：「上线需要 GitHub 账号授权，本程序不会保存你的密码。」+ 蓝色大按钮「**登录 GitHub 账号**」。

**你该点**：点它。然后——

1. 屏幕上**弹出一个黑色终端窗口**，自动执行 GitHub 登录命令；
2. 浏览器同时打开 GitHub 授权页，页面上显示一个 **8 位代码**（形如 `A1B2-C3D4`）；
3. 把代码**复制到黑窗口**里粘贴、回车；
4. 浏览器里点「Authorize」/「授权」；
5. 黑窗口出现 `Logged in as 你的用户名` 就成功了，**黑窗口可以直接关掉**。

界面上的按钮会变成「等待浏览器授权…」并转圈，**最长等 5 分钟**，检测到成功会自动继续。

| 按钮 / 文字 | 意思 |
| --- | --- |
| 登录 GitHub 账号 | 打开终端走浏览器授权（推荐） |
| 等待浏览器授权… | 正在等你完成上面几步，不用重复点 |
| 重新检测登录状态 | 你刚在别处登录过，点它立刻刷新 |
| 使用访问令牌登录 / 收起访问令牌登录 | 备用方案：到 GitHub `Settings → Developer settings → Personal access tokens` 生成一个带 `repo` 权限的令牌，粘进输入框点「用令牌登录」。令牌由 GitHub CLI 存在本机，程序不保存密码 |

**已登录时**会显示头像字母 + 用户名 + `github.com · https 协议 · 权限：…`。

### 卡片二：仓库与站点设置

| 项目 | 默认 | 说明 |
| --- | --- | --- |
| **仓库名** | 按站点名自动生成（英文小写，非法字符换 `-`） | 网址里的一段；旁边「按站点名生成」可重算。下方小字预告链接形如 `https://用户名.github.io/仓库名/` |
| **仓库描述** | 个人作品展示网站 | 只是给仓库写一句介绍 |
| **站点类型** | 项目站点 | 「项目站点」→ `https://用户名.github.io/仓库名/`；「用户站点」→ `https://用户名.github.io/`，且仓库名**必须正好是** `用户名.github.io`（界面有一键填好的链接） |
| **仓库可见性** | 公开 | **必须选公开**：私有仓库开网页托管要付费账号，免费账号会失败 |
| **提交信息** | `chore: 上线个人设计网站（由设计稿上线助手生成）` | Git 的提交说明，不影响使用 |

下方是大按钮「**开始上线**」。

### 卡片三：上线进度

一开始显示「等待开始…」和一行小字 `git init → commit → push → 开启 Pages → 复核`。点「开始上线」后变成实时进度条 + 滚动日志（最多 500 行）。

**你该点**：设置一般不用改，直接点「**开始上线**」，然后**什么都不用做，等着**。日志里出现英文命令是正常的——那是程序在替你敲命令。

**能等多久**：小站点一两分钟；首次上线的 Pages 构建通常还要 1~3 分钟（程序最多等 7 分钟）；总共可能等十几分钟，去喝杯水即可。

**如果出现「仓库 xxx 已经存在」**：程序会停下并给出确认条——

- 想**更新自己以前上线的网站** → 点「**覆盖推送（reuse: true）**」，然后**务必再点一次「开始上线」**；
- 想保留旧仓库 → 点「**换个仓库名**」，改个名字再点「开始上线」。

## 六、第五步：拿到链接

你会看到大卡片「**🎉 站点已上线**」+ 一行大号蓝色链接（点它用浏览器打开），以及三个按钮：

| 按钮 | 作用 |
| --- | --- |
| **复制链接**（点了变「已复制 ✓」） | 把网址复制到剪贴板——发给老师、同学、面试官就用它 |
| 打开仓库 | 打开这个网站在 GitHub 上的源代码仓库 |
| 查看构建日志 | 网站打不开时，看 GitHub 的构建记录（Actions 页） |

下面还有「**上线详情**」卡片（仓库地址、仓库全名、站点类型、Pages 状态、**HTTPS 强制开启** ✓/✗、提交号）和一行提示「Pages 首次构建可能需要 1~3 分钟，如果链接暂时 404，请稍等后再刷新」；以及「**上线复核报告**」卡片；还有一个「**再上线一个站点**」按钮（会清空当前导入、选择和结果，回到第 1 步）。

**到这里就完成了**，把链接发出去即可。

## 七、每个选项怎么选（取舍建议）

### 7.1 文本项：打码 / 删除 / 隐藏整块 / 保留

| 选项 | 效果 | 什么时候用 |
| --- | --- | --- |
| **打码**（推荐默认） | 原文替换成掩码：`181****6217`、`de***@example.com`、`杨**` | 大多数情况。保隐私又保留「这里原本有联系方式」的语义，排版不变 |
| **删除** | 删掉这几个字；如果整个条目因此变空（如「邮箱：xxx」只剩「邮箱：」），**程序会自动把这一行/这一块隐藏** | 该字段对作品集毫无意义时 |
| **隐藏整块** | 连同它所在的整个卡片/条目一起隐藏（布局保留，只是这块不显示） | 整张卡片都是隐私信息时 |
| **保留** | 原样公开 | 你确定可以公开的内容 |

**建议保留**（默认也是保留）：城市（如「昆明」，只到城市级）、学校名称、公司名称、社交平台账号链接（GitHub / 站酷 / Behance 等）、已打过码的手机号；「**疑似姓名（请人工确认）**」是程序猜的，很可能只是正文里一个普通词，**只有确实是你本人名字时才改成打码**。

**一定要处理**：身份证号、银行卡号、完整手机号、微信号、QQ 号、详细住址、学号/工号、任何 `sk-…` / `ghp_…` 之类的密钥令牌、私钥文件内容。

### 7.2 图片项：模糊打码 / 删除 / 保留

| 选项 | 效果 | 什么时候用 |
| --- | --- | --- |
| **模糊打码** | 整张图做真正的高斯模糊（并顺带清除拍摄信息）；插件装不上时会换成**同样大小**的斜纹占位图 | 证件照、工作照、生活照等不想被看清的照片。程序对「人像照片」的默认建议就是打码 |
| **删除** | 从上线目录里删掉这张图，页面里的引用会被摘掉 | 这张图根本不需要出现在作品集里 |
| **保留** | 原样保留（但仍会清掉 EXIF 与 GPS） | 作品截图、设计稿预览图等不含个人信息的图片 |

> 注意：**「模糊打码」是整张图模糊**，不是只糊脸。正式使用的证件照建议直接「删除」，另放一张打过码的图。

### 7.3 生成选项

- **清除照片里的 EXIF 与拍摄位置**：**保持勾选**（隐形泄露的重灾区）。
- **页面底部加「已脱敏」提示**：答辩/展示时勾上，能体现你的工作；正式对外发布可以不勾，观感更干净。
- **站点标题**：想改就填，例如「张三 · 视觉设计作品集」。

### 7.4 大文件要不要排除

| 情况 | 建议 |
| --- | --- |
| 单个文件 ≥ 100 MB | **必须排除**。GitHub 直接拒收，上线一定失败 |
| 单个文件 50~100 MB | **建议排除**。上传慢，以后每次更新都要重传 |
| 宣传视频、源文件（psd/ai/sketch/压缩包） | **建议排除**。网页上放压缩过的 mp4 就够了，源文件不该公开 |
| `_backup`、`_shots` 之类备份/截图目录 | **建议排除**（「扫描提示」里也会提醒你） |

勾选后页面里引用它们的部分会被自动摘掉（视频会整块隐藏），不会留下破图。

> 小知识：GitHub Pages 默认忽略**名字以下划线开头**的目录。本程序会写一个 `.nojekyll` 文件阻止这个行为，所以 `_backup` 只要**没被排除**就会被正常公开访问——**想藏起来请用排除，不要指望它自动隐身**。

## 八、上线成功之后

### 8.1 怎么验证

1. 在第 5 步点那个大链接；再用手机（**用流量，不要连家里 Wi-Fi**）打开同一个网址，确认别人也能访问。
2. 页面里按 `Ctrl` + `F` 搜你处理过的信息（手机号后四位、邮箱前缀等），**确认搜不到**。
3. 对着照片右键「在新标签页打开」，确认照片已被模糊或换成占位图。
4. 看「上线详情」里 **HTTPS 强制开启**是不是 ✓；若是 ✗，等几分钟到仓库 `Settings → Pages` 勾 **Enforce HTTPS**。
5. **界面上的「上线复核报告」可信度有限**（当前版本程序只确认了页面能打开），所以上面的第 2 步人工搜索**务必做一遍**。

### 8.2 怎么把链接发给别人

点第 5 步「**复制链接**」，粘贴到微信 / QQ / 邮件里。链接形如 `https://你的用户名.github.io/仓库名/`——**结尾的斜杠别丢**，否则可能 404。

### 8.3 怎么更新网站

**改完设计稿重新跑一遍即可：**

1. 第 1 步重新拖入（改过的）文件夹；
2. 第 2 步重新逐项确认（程序会重新扫描，之前的选择不会保留）；
3. 第 3 步重新生成，顺便点一下「本地预览」看看；
4. 第 4 步填**和上次完全一样的仓库名** →「开始上线」→ 弹出「仓库 xxx 已经存在」→ 点「**覆盖推送（reuse: true）**」→ **再点一次「开始上线」**；
5. 等 1~3 分钟，按 `Ctrl` + `F5` 强制刷新原来的网址就是新版了。

## 九、出错了怎么办

程序报错时会显示一个红色方框，里面有 `[错误码]` 和一句说明。按下面分类排查。

### 9.1 `E_NOT_LOGGED_IN` —— 还没登录 GitHub

1. 看第 4 步「GitHub 账号」卡片显示的是你的用户名，还是「未登录」。
2. 没登录就点「**登录 GitHub 账号**」：黑窗口要等它跑完，浏览器里要真的点了「Authorize」。
3. 若是「等了 5 分钟超时」：可能浏览器没弹出、代码没粘贴对、或黑窗口被中途关掉。**重新点一次「登录 GitHub 账号」即可**，多试几次通常就好。
4. 其实早就在别处登录过：点「**重新检测登录状态**」，或等 20 秒（程序每 20 秒自动刷新）。
5. 都不行就走备用路线：点「使用访问令牌登录」，粘贴带 `repo` 权限的 Personal Access Token。
6. 右侧面板里「GitHub CLI」若是红的，先点「重新检测」；还是红的说明自动安装失败（多半是网络），换个网络再试。

### 9.2 `E_REPO_EXISTS` —— 仓库已存在

1. 这不是故障，是程序在问你：`你的用户名/仓库名` 已被占用。
2. **更新自己以前的网站** → 点「**覆盖推送（reuse: true）**」 → **务必再点一次「开始上线」**（只点确认条不会开始上线）。
3. **不动旧仓库** → 点「**换个仓库名**」，改成别的（加个 `-2`、换个英文短名），再点「开始上线」。
4. 同名仓库属于别人时你无权覆盖，只能换名字。

### 9.3 `E_PAGES` —— GitHub Pages 相关失败

**（1）「无法为私有仓库开启 Pages」**：免费账号不支持私有仓库的网页托管。回第 4 步把「**仓库可见性**」改成「**公开**」，再上线一次。

**（2）「Pages 构建失败（errored）」**：点「**查看构建日志**」打开仓库 `Actions` 页看红色那条。最常见原因是站点根目录没有 `index.html`（见第一步的小贴士）；其次是生成目录太大（Pages 有约 1 GB 的站点软限制），回第 3 步排除大文件重新生成。修好后同仓库名 + 覆盖推送重跑。

**（3）多数情况其实不是错误**：界面只提示「等待 Pages 构建超时，仍返回链接供你稍后查看」——链接已经给你了，**等 1~3 分钟再刷新**即可打开。

### 9.4 `E_GIT` —— Git 相关失败

1. 先看错误信息里 `git` 后面那句话，通常能直接看出原因。
2. **「未找到 Git」**：右侧面板点「重新检测」，程序会用 winget 自动装；若提示没有 winget，自己去 <https://git-scm.com/download/win> 下载安装（一路下一步），装完**重启程序**。
3. **「推送失败」**：检查网络（公司网/校园网可能挡 GitHub）→ 确认仓库属于你、你有写权限 → 若提示仓库名被占，回第 4 步换名 → 若提示文件超限（`exceeds GitHub's file size limit`），回第 3 步排除它重新生成。
4. **「git commit 失败」**：多半是生成目录里有个 `.gitignore` 在作怪（日志里有「站点目录里存在 .gitignore」的提示，删掉它再试），或者磁盘没空间。
5. 重试前建议关掉程序再打开，避免上次的临时状态残留。

### 9.5 其它常见错误

| 你看到的 | 原因 | 怎么办 |
| --- | --- | --- |
| `E_NOT_FOUND`：路径不存在 | 文件夹被移动/删除了 | 回第 1 步重新拖一次 |
| `E_BAD_INPUT`：多个含 index.html 的子目录 | 程序不知道选哪个 | 按提示直接选中其中一个子目录 |
| `E_BAD_INPUT`：用户站点仓库名必须是 `用户名.github.io` | 类型选了「用户站点」但仓库名不对 | 点一键填入的链接，或改回「项目站点」 |
| `E_NO_GH`：未找到 GitHub CLI | 自动安装失败 | 右侧面板「重新检测」重装；或从 <https://cli.github.com> 手动安装 |
| `E_NET`：端口被占用或无法监听 | 本地预览起不来 | 关掉占用端口的程序，重新点「本地预览」 |
| `E_AUTH`：登录失败 / 令牌登录失败 | 令牌权限不足或已失效 | 重新生成带 `repo` 权限的令牌，或改用浏览器授权 |
| `E_UNKNOWN` | 程序内部意外错误 | 把红色框文字 + 底部日志（最多 500 行）截图给开发者 |
| 图片打码插件一直是红的 | sharp 没装上 | **不影响使用**，图片自动改用同尺寸占位图；网络恢复后点「重新检测」 |

### 9.6 网站打开了但是 404

按顺序排查：等 1~3 分钟再刷新 → 确认链接里有仓库名和结尾的 `/` → 确认仓库里有 `index.html` → 确认仓库是**公开**的 → 到仓库 `Settings → Pages` 看分支是不是 `main`、目录是不是 `/`。

### 9.7 程序生成的文件在哪

按 `Alt` 打开菜单栏 →「**文件**」→「**打开工作区目录**」（所有上线目录与脱敏报告都在这）或「**打开插件目录**」（自动装的 GitHub CLI 与打码插件）。

## 十、按钮速查表

| 位置 | 按钮 | 作用 |
| --- | --- | --- |
| 第 1 步 | 选择文件夹 / 选择 index.html / 重新选择目录 | 导入站点、重选目录 |
| 第 2 步 | 全部打码 / 全部删除 / 全部隐藏整块 / 全部保留 | 批量设置，**只对当前筛选生效** |
| 第 2 步 | 查看命中位置（N）/ 添加 / × | 展开每处命中位置、增删自定义关键词 |
| 第 3 步 | 生成上线目录 / 打开目录 / 打开脱敏报告 / 本地预览 / 停止预览 | 生成、查看结果、预览 |
| 第 4 步 | 登录 GitHub 账号 / 重新检测登录状态 / 用令牌登录 / 按站点名生成 / 开始上线 | 登录与上线 |
| 第 4 步 | 覆盖推送（reuse: true）/ 换个仓库名 | 仓库重名时的两个选择（选完要再点一次「开始上线」） |
| 第 5 步 | 复制链接 / 打开仓库 / 查看构建日志 / 再上线一个站点 | 拿链接、查仓库、看构建、重新开始 |
| 底部 / 右侧面板 | 上一步 · 下一步（第 4 步叫「查看结果」）/ 重新检测 | 步骤切换、重装缺失插件 |
